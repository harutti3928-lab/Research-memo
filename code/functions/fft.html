FFT — フーリエ変換と主要配列の確保

— (k, iω) ⇔ (r, τ) の高速フーリエ変換と、FLEX 主要配列（G・CHI・SIGMA）の確保  |  関数名をクリックで詳細 —

FLEX の畳み込み（χ0 = G·G や Σ = V·G）は、運動量・松原周波数 (k, iω) 表示のままだと 畳み込み積分になって重い。これを実空間・虚時間 (r, τ) に移すと 単なる要素ごとの積に落ちる。このファイルは、その行き来を担う forward / inverse FFT（kw2rt! / rt2kw!）と、ループで使い回す主要配列 G・CHI・SIGMA と FFT プランの一括確保（initialize_main_arrays）をまとめたもの。 Nonint が作った H(k) を土台に、ここで確保した配列の上で FLEX の SCF が回る。

このページの規約：FFT プランは先頭 4 軸（周波数 iω と運動量 kx,ky,kz）をまとめて変換する ＝ (k,iω)→(r,τ) を一度に行う。G と CHI は先頭 4 軸の形 2Nw × Nqx × Nqy × Nqz が共通なので プランを 1 つ使い回す。周波数軸は 2Nw（松原周波数の全域＝畳み込みで折り返しを避けるための倍長）で確保する。軌道ループの ブロック順は for j, for i（j が外, i が内）で Nonint と揃える。

fft_transform.jl — 冒頭
# fft_transform.jl
# (k, iω) ⇔ (r, τ) の高速フーリエ変換と、FLEX 主要配列の確保。
# χ0 や Σ の畳み込みを実空間・虚時間で積に落とすために使う。

using FFTW
using LinearAlgebra
using Base.Threads
kw2rt!▶ 6 階配列を forward FFT して (k,iω) → (r,τ) に変換（in-place）
kw2rt!(arr::Array{ComplexF64,6}, FFT_plan) # 破壊的：arr を (r,τ) 表示へ上書き

概要

6 階配列 arr[iw, kx, ky, kz, i, j] の先頭 4 軸（周波数＋運動量）を forward FFT し、 (k,iω) 表示から (r,τ) 表示へ変換する。軌道添字 (i,j) ごとに 4 次元スライスを FFT し、その結果を arr 自身へ書き戻す in-place 変換。 書き戻しの走査は k 点 q についてスレッド並列化している。

コード

fft_transform.jl · kw2rt!
function kw2rt!(arr::Array{ComplexF64,6}, FFT_plan)
    NW, Nqx, Nqy, Nqz, M, _ = size(arr)
    Nq = Nqx * Nqy * Nqz
    tmp = Array{ComplexF64}(undef, NW, Nqx, Nqy, Nqz)
    arr_view = reshape(arr, NW, Nq, M, M)
    tmp_view = reshape(tmp, NW, Nq)
    for j in 1:M, i in 1:M
        mul!(tmp, FFT_plan, arr[:, :, :, :, i, j])
        @threads for q in 1:Nq
            @views arr_view[:, q, i, j] .= tmp_view[:, q]
        end
    end
end

読み方

  • 関数名末尾の ! は Julia の慣習で 「引数を破壊的に書き換える（in-place）」ことを表す。戻り値ではなく arr 自体が (r,τ) 表示に更新される。
  • NW, Nqx, Nqy, Nqz, M, _ = size(arr) — 周波数点数 NW、k メッシュ、軌道数 M を取り出す。最後の軸も同じ M なので _ で捨てる。
  • tmp = Array{ComplexF64}(undef, NW,Nqx,Nqy,Nqz) — FFT の出力を受ける連続メモリの作業配列。プランと同じ 4 次元形状。
  • arr_view = reshape(arr, NW, Nq, M, M) / tmp_view = reshape(tmp, NW, Nq) — コピーせずに「k を 1 本（Nq）に潰した」ビューを作る。書き戻しを q の 1 重ループで回すための下ごしらえ。
  • for j in 1:M, i in 1:M — 軌道ペアごとに処理。ブロック順は j 外・i 内で Nonint と共通。
  • mul!(tmp, FFT_plan, arr[:,:,:,:,i,j]) — (i,j) スライスにプランを適用し、結果を tmp に書く。mul! は「プラン × 入力」＝ forward FFT。右辺の arr[...] はスライスのコピーで、これが FFT の入力になる。
  • @threads for q ... @views arr_view[:,q,i,j] .= tmp_view[:,q] — 変換結果を arr の (i,j) ブロックへ書き戻す。各 q は互いに独立な列を書くだけなので、スレッド並列にしても競合しない。@views でスライスの一時配列生成を抑える。
なぜ tmp を経由するのか： arr[:,:,:,:,i,j] は中央 2 軸で切り出したスライスでメモリが連続していないため、mul! の出力先に直接は使いにくい。そこで連続な tmp に一度 FFT し、その後 q 単位で arr に書き戻している。FFT_plan の形（2Nw×Nqx×Nqy×Nqz）と arr の先頭 4 軸が一致していることが前提。
関連：rt2kw!（逆変換で (k,iω) に戻す）／ initialize_main_arrays（FFT_plan を供給）
rt2kw!▶ inverse FFT で (r,τ) → (k,iω) に戻す（kw2rt! の逆・in-place）
rt2kw!(arr::Array{ComplexF64,6}, FFT_plan) # 破壊的：arr を (k,iω) 表示へ戻す

概要

kw2rt! の逆変換。同じ FFT_plan を使い、ldiv!（プランで割る＝ inverse FFT）で (r,τ) 表示を (k,iω) に戻す。構造は kw2rt! と全く同じで、 mul! を ldiv! に替えただけ。

コード

fft_transform.jl · rt2kw!
function rt2kw!(arr::Array{ComplexF64,6}, FFT_plan)
    NW, Nqx, Nqy, Nqz, M, _ = size(arr)
    Nq = Nqx * Nqy * Nqz
    tmp = Array{ComplexF64}(undef, NW, Nqx, Nqy, Nqz)
    arr_view = reshape(arr, NW, Nq, M, M)
    tmp_view = reshape(tmp, NW, Nq)
    for j in 1:M, i in 1:M
        ldiv!(tmp, FFT_plan, arr[:, :, :, :, i, j])
        @threads for q in 1:Nq
            @views arr_view[:, q, i, j] .= tmp_view[:, q]
        end
    end
end

読み方

  • kw2rt! と形は同一。違いは変換の向きだけ（reshape や書き戻しの並列化はそのまま）。
  • ldiv!(tmp, FFT_plan, arr[:,:,:,:,i,j]) — プランで「割る」＝ FFT_plan \ 入力 で 正規化付きの逆 FFT。1/N の規格化はこの ldiv! 側に入っているので、 kw2rt! → rt2kw! と続けると元に戻る（恒等）。
  • あとの @threads for q の書き戻しは kw2rt! と同じ。各 q が独立な列で並列安全。
mul! と ldiv! は対： forward（mul!）は非正規化、inverse（ldiv!）は 1/N 込み。往復すれば係数はちょうど戻るので、自前で 1/N を掛けないこと（二重に割ると値が縮む）。 FLEX ループでは「kw2rt! で (r,τ) に落とす → その場で積を取る → rt2kw! で戻す」の 3 点セットで使う。
関連：kw2rt!（順変換）／ initialize_main_arrays（同じ FFT_plan を供給）
initialize_main_arrays▶ FLEX 主要配列（G・CHI・FFT_plan・任意で SIGMA）を一括確保
initialize_main_arrays(Nw, Nqx, Nqy, Nqz, Norb, Nco; init_SIGMA=true) → (G, CHI, FFT_plan[, SIGMA])

概要

FLEX の SCF ループで使い回す主要配列を一括で確保する。グリーン関数 G、感受率系の作業配列 CHI、そして G の 4 次元サブブロック上に張った FFT_plan を返す。 init_SIGMA=true なら自己エネルギー SIGMA も 0 初期化で追加して返す （SCF の初回は Σ=0 から始めるため）。

コード

fft_transform.jl · initialize_main_arrays
function initialize_main_arrays(Nw, Nqx, Nqy, Nqz, Norb, Nco; init_SIGMA=true)
    G = Array{ComplexF64}(undef, 2 * Nw, Nqx, Nqy, Nqz, Norb, Norb)
    CHI = Array{ComplexF64}(undef, 2 * Nw, Nqx, Nqy, Nqz, Nco, Nco)
    FFT_plan = plan_fft(G[:, :, :, :, 1, 1], [1, 2, 3, 4])
    if init_SIGMA
        SIGMA = zeros(ComplexF64, (Nw, Nqx, Nqy, Nqz, Norb, Norb))
        return G, CHI, FFT_plan, SIGMA
    else
        return G, CHI, FFT_plan
    end
end

読み方

  • G = Array{ComplexF64}(undef, 2*Nw, Nqx,Nqy,Nqz, Norb,Norb) — グリーン関数。周波数軸は 2Nw（松原周波数の全域）。undef なのは、使う前に H(k) などから全上書きされるので初期化不要だから。
  • CHI = Array{ComplexF64}(undef, 2*Nw, ..., Nco, Nco) — 感受率系の作業配列。軌道は複合添字 Nco（軌道ペアをまとめた次元＝多軌道の χ を行列として扱う）で、先頭 4 軸は G と同じ形。だからプランを共有できる。
  • FFT_plan = plan_fft(G[:,:,:,:,1,1], [1,2,3,4]) — G の 4 次元サブブロック (2Nw×Nqx×Nqy×Nqz) 上に、4 軸すべて（周波数＋3 運動量）を変換するプランを作る。G・CHI は この形が共通なので、この 1 プランを両方に使い回す。入力の G[...,1,1] はコピーなので、プラン作成でその中身が汚れても無害。
  • if init_SIGMA … zeros(ComplexF64, (Nw, ...)) — 自己エネルギー SIGMA を確保。周波数軸は Nw（2Nw ではない）。undef でなく zeros なのは、SCF の初回反復を Σ=0 から始めるため。
  • return G, CHI, FFT_plan[, SIGMA] — init_SIGMA の真偽で、SIGMA を含める / 含めないを分岐して返す。
周波数軸の長さに注意： G・CHI は 2Nw、SIGMA は Nw と異なる。 FFT する G/CHI 側だけが倍長（畳み込みの折り返し回避）で、SIGMA は物理的な松原窓のまま持つ、という役割分担。 undef（G/CHI）と zeros（SIGMA）の違いも「後で全上書きするか / 初期値として 0 が要るか」の差。
関連：kw2rt! · rt2kw!（この FFT_plan を使う）／ Nonint の H(k)（G の構築材料）
全体の流れ： Nonint で H(k)・バンドを用意 → initialize_main_arrays で G・CHI・SIGMA・FFT_plan を確保 → FLEX ループ内で kw2rt! により (r,τ) に落として χ0=G·G や Σ=V·G を要素積で計算 → rt2kw! で (k,iω) に戻す。 この FFT 往復が FLEX の畳み込みを高速化する心臓部になる。
