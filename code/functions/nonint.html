Nonint — 非相互作用ハミルトニアン

— hop.dat から H(k) を組み、対角化してバンドを得る「一体問題」のコード  |  関数名をクリックで詳細 —

Wannier90 が出力した実空間ホッピング積分 hop.dat（tight-binding パラメータ tij(R)）を出発点に、逆空間のハミルトニアン H(k) = ΣR tij(R) e-ik·R を組み立て、各 k 点で対角化して バンド固有値と固有ベクトル（ユニタリ行列）を得るまでを担う。ここで作った H(k) と UNITARY が、後段の FLEX（自己エネルギー・感受率）や Eliashberg（ギャップ方程式）の 土台になる。

このページの規約：k メッシュは fftfreq(N, 2π) で生成（後段 FLEX の FFT と同じ並び）、 位相はセル並進 R のみ（サブラティス内座標は含めない = convention I）、 hop.dat のブロック順は for j, for i（j が外, i が内）。この3点が全関数で共通の前提。

hop.dat の読み込みと H(k) の構築・対角化・ゲージ固定をまとめたファイル。冒頭の依存パッケージは次のとおり。

hamiltonian.jl — 冒頭
# hamiltonian.jl
# hop.dat の読み込みと H(k) の構築・対角化・ゲージ固定。

using LinearAlgebra
using Base.Threads
using CSV, DataFrames
using FFTW: fftfreq
load_Hamiltonian▶ hop.dat を読み、正則 k メッシュ上で H(k)=ΣR t(R)e-ik·R を構築（メインの構築関数）
load_Hamiltonian(hopping_file::String, Nqx, Nqy, Nqz, Norb::Int; return_df=false) → ENERGY[kx,ky,kz,i,j]

概要

hop.dat（列 = Rx Ry Rz Re(t) Im(t)）を読み込み、分割数 Nqx×Nqy×Nqz の正則な k メッシュ上で ENERGY[kx,ky,kz,i,j] = ΣR tij(R) e-ik·R を計算して 5 次元複素配列で返す。return_df=true なら読み込んだ DataFrame も一緒に返す （後述の hamiltonian_from_hopping_df でそのまま使える）。

コード

hamiltonian.jl · load_Hamiltonian
function load_Hamiltonian(hopping_file::String, Nqx::Int, Nqy::Int, Nqz::Int, Norb::Int; return_df::Bool=false)
    hopping_df = CSV.read(
        hopping_file, DataFrame;
        header=[:x, :y, :z, :hop_real, :hop_cmplx], delim=" ", ignorerepeated=true, silencewarnings=true,
    )
    # 虚部列が欠けている行は 0 で埋める
    hopping_df[!, :hop_cmplx] .= coalesce.(hopping_df[!, :hop_cmplx], 0.0)

    kx, ky, kz = map(N -> fftfreq(N, 2π), [Nqx, Nqy, Nqz])
    kxg = reshape(kx, 1, Nqx, 1, 1)
    kyg = reshape(ky, 1, 1, Nqy, 1)
    kzg = reshape(kz, 1, 1, 1, Nqz)
    phase = kxg .* hopping_df[:, :x] .+ kyg .* hopping_df[:, :y] .+ kzg .* hopping_df[:, :z]
    hopping = hopping_df[:, :hop_real] + im * hopping_df[:, :hop_cmplx]

    ENERGY = Array{ComplexF64}(undef, Nqx, Nqy, Nqz, Norb, Norb)
    Nrvec = size(hopping_df)[1] ÷ Norb^2
    s, e = 1, Nrvec
    for j in 1:Norb, i in 1:Norb
        ENERGY[:, :, :, i, j] .= sum(hopping[s:e, :, :, :] .* exp.(-im * phase[s:e, :, :, :]), dims=1)[1, :, :, :]
        s += Nrvec
        e += Nrvec
    end

    # H = H† のチェック（hop.dat / Norb の指定ミス検出）
    if !(ENERGY ≈ conj(permutedims(ENERGY, (1, 2, 3, 5, 4))))
        @warn "Hamiltonian is not Hermitian! Check the hopping file and Norb."
    end

    return return_df ? (ENERGY, hopping_df) : ENERGY
end

読み方

  • CSV.read(...; header=[:x,:y,:z,:hop_real,:hop_cmplx], delim=" ", ignorerepeated=true) — hop.dat をスペース区切りで読み込む。ignorerepeated=true は「連続する空白を1つの区切りとして扱う」設定で、桁揃えされたテキスト表を安全に読むための肝。
  • coalesce.(hopping_df[!, :hop_cmplx], 0.0) — 虚部の列が空（missing）だった行を 0.0 で埋める。実数ホッピングだけの hop.dat でも落ちないようにする防御。
  • map(N -> fftfreq(N, 2π), [Nqx,Nqy,Nqz]) — 各方向の k 点を生成。fftfreq を使うのは、後段 FLEX の FFT と全く同じ順序・規約で k を並べるため。並びは 0, 2π/N, …, -2π/N のような順（0 の次が正、後半が負）になる。
  • reshape(kx, 1, Nqx, 1, 1) ほか — kx,ky,kz を 異なる軸に差し込む。こうすると次の行でブロードキャストするだけで 3 次元 k グリッドの位相が一気に作れる。
  • phase = kxg.*x + kyg.*y + kzg.*z — 各 R 行 × 各 k 点の 位相 k·R。形は (Nrows, Nqx, Nqy, Nqz)（R が第1軸、残り 3 軸が k グリッド）。
  • hopping = hop_real + im*hop_cmplx — 複素ホッピング t = Re + i·Im をまとめる。
  • Nrvec = size(...)[1] ÷ Norb^2 — 全行数を Norb² で割って、1 軌道ペアあたりの R ベクトル数を求める。÷ は整数除算。
  • for j in 1:Norb, i in 1:Norb + s, e スライス — hop.dat のブロック順（j が外, i が内）に合わせて Norb² 個のブロックを順に切り出す。s:e が「今のペア (i,j) の R ブロック」。ループ末尾で s,e を Nrvec ずつ進める。
  • sum(hopping[s:e] .* exp.(-im*phase[s:e]), dims=1) — R について和を取り Hij(k)=ΣR t e-ik·R を得る。[1,:,:,:] で潰れた R 軸を落として (Nqx,Nqy,Nqz) に整形。
  • ENERGY ≈ conj(permutedims(ENERGY, (1,2,3,5,4))) — 最後の 2 軸（軌道 i,j）を入れ替えて共役、すなわち H(k)† と一致するか＝エルミート性を確認。ずれていれば Norb か hop.dat の指定ミスとして警告。
  • return return_df ? (ENERGY, hopping_df) : ENERGY — フラグ次第で DataFrame も返す三項演算。
つまずきポイント： ブロック順が「j 外・i 内」である前提。ここを取り違える（i 外・j 内で読む）と H が非エルミートになり、末尾の警告が出る。Norb の値ミスでも全行数が Norb² で割り切れず結果が壊れるので、警告が出たらまずこの 2 つを疑う。
関連：hamiltonian_from_hopping_df（同じ規約で k-path 用）／ diagonalize_Hamiltonian（この ENERGY を対角化）
hamiltonian_from_hopping_df▶ 任意の k 点列（k-path）上で H(k) を構築 — バンド図用
hamiltonian_from_hopping_df(hopping_df, Norb::Int, k_cart::AbstractMatrix) → Hk[Nk,Norb,Norb]

概要

正則メッシュではなく、任意の k 点列 k_cart = 2π·k_frac（Nk×3）上で H(k) を作る。主に高対称点を結ぶ k-path 上のバンド計算に使う。位相・ブロック順は load_Hamiltonian と完全に同一で、実装だけ「ブロードキャスト＋sum」から「行列積」に替えたもの。

コード

hamiltonian.jl · hamiltonian_from_hopping_df
function hamiltonian_from_hopping_df(hopping_df, Norb::Int, k_cart::AbstractMatrix{<:Real})
    Nk = size(k_cart, 1)
    x = Vector{Float64}(hopping_df[:, :x])
    y = Vector{Float64}(hopping_df[:, :y])
    z = Vector{Float64}(hopping_df[:, :z])
    hop = Vector{ComplexF64}(hopping_df[:, :hop_real] .+ im .* hopping_df[:, :hop_cmplx])

    total_rows = length(hop)
    if total_rows % (Norb^2) != 0
        throw(ArgumentError("hopping_df rows ($total_rows) is not divisible by Norb^2 ($(Norb^2)). Check Norb and hopping file."))
    end
    Nrvec = total_rows ÷ (Norb^2)

    Hk = Array{ComplexF64}(undef, Nk, Norb, Norb)
    s = 1
    for j in 1:Norb, i in 1:Norb
        e = s + Nrvec - 1
        r = hcat(@view(x[s:e]), @view(y[s:e]), @view(z[s:e]))  # Nrvec×3
        phase = r * transpose(k_cart)                          # Nrvec×Nk
        expp = exp.(-im .* phase)
        vals = transpose(expp) * @view(hop[s:e])               # Nk
        @views Hk[:, i, j] .= vals
        s = e + 1
    end
    return Hk
end

読み方

  • hopping_df は load_Hamiltonian(...; return_df=true) が返した DataFrame をそのまま渡す想定。k_cart は デカルト（=2π 倍済み）の k 点並び Nk×3。
  • x, y, z, hop を Vector に取り出す — DataFrame から生配列にしておき、以降の行列演算を速くする。
  • if total_rows % (Norb^2) != 0 … throw(ArgumentError(...)) — 行数が Norb² で割り切れなければ、Norb か hop.dat が不整合だと判断して即エラー停止。load_Hamiltonian の「警告」より厳しく、早期に気づける。
  • for j, for i — ここもブロック順は j 外・i 内で共通。s, e で今のペアの R ブロックを切り出す。
  • r = hcat(x[s:e], y[s:e], z[s:e]) — 今のブロックの R ベクトルを Nrvec×3 行列に。@view はコピーを作らず参照するだけ（メモリ節約）。
  • phase = r * transpose(k_cart) — (Nrvec×3)·(3×Nk) = Nrvec×Nk の行列積で、全 R × 全 k の内積 k·R を一括計算。
  • vals = transpose(expp) * hop[s:e] — (Nk×Nrvec)·(Nrvec) = Nk。この行列積が R についての和そのもので、各 k の Hij(k) を与える。
  • @views Hk[:, i, j] .= vals — 結果を格納。@views で右辺スライスの一時配列生成を抑える。
load_Hamiltonian との違い： 中身の数式は同一（同じ位相・同じブロック順）。違うのは「正則メッシュを 4 次元ブロードキャストで一気に作る」か「任意の k 列を行列積で作る」かだけ。前者は FLEX 用の格子データ、後者はバンド図の滑らかな k-path 用と役割を分けている。
関連：load_Hamiltonian（return_df=true で df を供給）／ diagonalize_Hk（この Hk を対角化）
diagonalize_Hamiltonian▶ 格子 H(k)（＋任意で静的自己エネルギー）を各 k で対角化 → バンドと固有ベクトル
diagonalize_Hamiltonian(ENERGY; SIGMA=nothing) → (ENERGY_diag[kx,ky,kz,band], UNITARY[kx,ky,kz,:,band])

概要

load_Hamiltonian が返した 5 次元 ENERGY を各 k 点で対角化し、バンド固有値 ENERGY_diag と固有ベクトル UNITARY を返す。オプションで 静的自己エネルギー self0（FLEX の SIGMA の最低松原成分をエルミート化したもの）を H(k) に足してから 対角化でき、繰り込まれた準粒子バンドが得られる。

コード

hamiltonian.jl · diagonalize_Hamiltonian
function diagonalize_Hamiltonian(ENERGY::Array{ComplexF64,5}; SIGMA::Union{Array{ComplexF64,6},Nothing}=nothing)
    Nqx, Nqy, Nqz, No, _ = size(ENERGY)
    Nq = Nqx * Nqy * Nqz
    ENERGY_diag = Array{Float64,4}(undef, Nqx, Nqy, Nqz, No)
    UNITARY = Array{ComplexF64,5}(undef, Nqx, Nqy, Nqz, No, No)
    ENERGY_diag_view = reshape(ENERGY_diag, Nq, No)
    UNITARY_view = reshape(UNITARY, Nq, No, No)
    ENERGY_view = reshape(ENERGY, Nq, No, No)

    flag = SIGMA !== nothing
    if flag
        SIGMA_view = reshape(SIGMA, size(SIGMA)[1], Nq, No, No)
        self0 = Array{ComplexF64}(undef, Nq, No, No)
        for j in 1:No, i in 1:No
            self0[:, i, j] .= 0.5 * (SIGMA_view[1, :, i, j] + conj(SIGMA_view[1, :, j, i]))
        end
    end

    @threads for q in 1:Nq
        if flag
            @views self0[q, :, :] .+= ENERGY_view[q, :, :]
            w, v = eigen(self0[q, :, :])
        else
            w, v = eigen(ENERGY_view[q, :, :])
        end
        ENERGY_diag_view[q, :] .= real.(w)
        UNITARY_view[q, :, :] .= v
    end
    return ENERGY_diag, UNITARY
end

読み方

  • Nqx,Nqy,Nqz,No,_ = size(ENERGY) — メッシュ寸法と軌道数 No を取り出す（最後の軸は同じ No なので _ で捨てる）。Nq は全 k 点数。
  • reshape(..., Nq, No, No) 系 — 5 次元配列を コピーせず「k を 1 本に潰した」ビューにする。以降 q の 1 重ループで全 k を回せる。
  • flag = SIGMA !== nothing — 自己エネルギーが渡されたかの判定。渡されなければ純粋な H(k) を対角化する（＝非相互作用バンド）。
  • self0[:,i,j] .= 0.5*(Σ[1,:,i,j] + conj(Σ[1,:,j,i])) — 静的自己エネルギー。最低松原周波数 [1] の Σ を ½(Σ + Σ†) でエルミート化して取り出す（数値誤差で崩れた対称性をならす）。
  • @threads for q in 1:Nq — k 点ごとにスレッド並列で対角化。各 k は独立なので素直に並列化できる。
  • self0[q] .+= ENERGY_view[q] → eigen(self0[q]) — H(k)+self0 を対角化（flag=true）。flag=false なら eigen(H(k)) をそのまま。
  • ENERGY_diag_view[q,:] .= real.(w) — 固有値 w の実部をバンドとして格納。eigen は一般（非エルミート可）の対角化なので、実バンドは real を取って確定させる。
  • UNITARY_view[q,:,:] .= v — 固有ベクトル行列 v を格納。列 UNITARY[...,:,band] が各バンドの固有ベクトル。
なぜ Hermitian を使わないか： self0 を足すと（自己エネルギーの反エルミート成分などで）厳密なエルミート行列でなくなり得るため、汎用の eigen を使い固有値は real で確定させている。純粋な一体バンドだけが必要なら、次の diagonalize_Hk のように Hermitian を明示する方が数値的に安定。
関連：load_Hamiltonian（入力 ENERGY を供給）／ fix_unitary_gauge!（UNITARY の位相を整える）／ FLEX の SIGMA
diagonalize_Hk▶ k-path 用の H(k) リスト（Nk×Norb×Norb）を Hermitian 対角化 → E, U
diagonalize_Hk(Hk::Array{ComplexF64,3}; hermitize=true) → (E[Nk,Norb], U[Nk,Norb,Norb])

概要

hamiltonian_from_hopping_df が作った Hk（Nk×Norb×Norb）を各 k で対角化して、 バンド E と固有ベクトル U を返す。バンド図を描くときの対角化係。Hermitian 型を明示して対角化するので、実固有値・直交固有ベクトルが保証され数値的に安定。

コード

hamiltonian.jl · diagonalize_Hk
function diagonalize_Hk(Hk::Array{ComplexF64,3}; hermitize::Bool=true)
    Nk, Norb, _ = size(Hk)
    E = Array{Float64}(undef, Nk, Norb)
    U = Array{ComplexF64}(undef, Nk, Norb, Norb)
    for ik in 1:Nk
        H = @view(Hk[ik, :, :])
        Hmat = hermitize ? (H + H') .* 0.5 : H
        F = eigen(Hermitian(Matrix(Hmat)))
        E[ik, :] .= F.values
        U[ik, :, :] .= F.vectors
    end
    return E, U
end

読み方

  • Nk, Norb, _ = size(Hk) — k 点数と軌道数を取得。
  • H = @view(Hk[ik, :, :]) — ik 番目の k の Norb×Norb 行列を参照（コピーなし）。
  • Hmat = hermitize ? (H + H').*0.5 : H — hermitize=true なら ½(H+H†) で強制的にエルミート化。数値誤差で崩れた対称性をならしてから対角化する保険。
  • eigen(Hermitian(Matrix(Hmat))) — Hermitian 型でラップして対角化。実固有値・直交する固有ベクトルが保証され、diagonalize_Hamiltonian の汎用 eigen より安定・高速。
  • E[ik,:] .= F.values / U[ik,:,:] .= F.vectors — 固有値・固有ベクトルを格納。Hermitian 経由なので固有値は昇順に並ぶ。
使い分け： 格子（FLEX 用の正則メッシュ・自己エネルギー込み）なら diagonalize_Hamiltonian、 バンド図（k-path・一体のみ）なら diagonalize_Hk。後者は Hermitian で固有値がソート済みになるので、そのまま線でつないでバンドが描ける。
関連：hamiltonian_from_hopping_df（入力 Hk を供給）／ diagonalize_Hamiltonian（格子版）
fix_unitary_gauge!▶ 固有ベクトルの位相（ゲージ）を固定 — k ごとのランダム位相を除去（in-place）
fix_unitary_gauge!(UNITARY::Array{ComplexF64,5}) # 破壊的：UNITARY を直接書き換える

概要

各固有ベクトルの全体位相の不定性（ゲージ）を固定する。具体的には「絶対値が最大の成分の位相を 0 に合わせる」。 eigen が返す固有ベクトルは eiθ 倍の自由度が k ごとにバラバラなので、これを揃えることで バンド／固有ベクトルが k に対して滑らかにつながるようにする。

コード

hamiltonian.jl · fix_unitary_gauge!
function fix_unitary_gauge!(UNITARY::Array{ComplexF64,5})
    Nqx, Nqy, Nqz, Norb, _ = size(UNITARY)
    @threads for z in 1:Nqz
        for y in 1:Nqy, x in 1:Nqx
            for b in 1:Norb
                v = UNITARY[x, y, z, :, b]
                idx = argmax(abs.(v))
                theta = angle(v[idx])
                UNITARY[x, y, z, :, b] .*= exp(-im * theta)
            end
        end
    end
end

読み方

  • 関数名末尾の ! は Julia の慣習で 「引数を破壊的に書き換える（in-place）」ことを表す。戻り値ではなく UNITARY 自体が更新される。
  • @threads for z … for y,x … for b — 全 k 点 × 全バンド b を走査（z ループをスレッド並列化）。
  • v = UNITARY[x,y,z,:,b] — バンド b の固有ベクトルを取り出す。
  • idx = argmax(abs.(v)) — 絶対値が最大の成分の位置。位相の基準にこの成分を選ぶ（振幅が大きく数値的に安定な成分）。
  • theta = angle(v[idx]) — その基準成分の位相 θ。
  • UNITARY[...] .*= exp(-im*theta) — ベクトル全体に e-iθ を掛け、基準成分を実正にして位相を固定。
注意： これは「最大成分基準」の簡便なゲージ固定で、k 全域での厳密に滑らかな接続（Berry 接続の連続化）を保証するものではない。ただし k ごとのランダム位相を除くには実用上十分で、可視化や後段処理の前処理として使う。
関連：diagonalize_Hamiltonian（UNITARY を生成）／ diagonalize_Hk
全体の流れ： load_Hamiltonian（hop.dat → 格子 H(k)）→ diagonalize_Hamiltonian（各 k で対角化）→ fix_unitary_gauge!（位相を整える）が FLEX/Eliashberg へ渡す標準ルート。 バンド図を描くときは load_Hamiltonian(...; return_df=true) → hamiltonian_from_hopping_df（k-path）→ diagonalize_Hk の別ルートを使う。
