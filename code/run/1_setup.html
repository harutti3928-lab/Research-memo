1. Setup — 非相互作用セットアップ

— hop.dat から H(k) を組み、μ・占有数・k-path バンドを計算して simulation.h5 に保存する準備スクリプト  |  関数名をクリックで詳細 —

AA-stack bilayer honeycomb の非相互作用セットアップ。後段 FLEX / Eliashberg の土台（H(k)・対角化・μ・k-path バンド）を作って simulation.h5 に保存する、パイプライン最初のスクリプト。モデルのホッピングは gen_hop.py が書き出す hop.dat に外出しされ、この 1_setup.jl は それを読んで一体問題を解き、結果を HDF5 に固める役割を担う。

使い方： まず python gen_hop.py --t 1.0 --tpp -0.5 --t_perp 0.8 -o hop.dat で hop.dat を作り、 続けて julia --project=. 1_setup.jl。
入力： hop.dat（＋任意で KPOINTS）。
出力： simulation.h5（params / nonint 各グループ）、Noint/band_kpath.dat。
依存： include("functions/nonint.jl")（Nonint の関数群を読み込む）。
hop.dat→ load_Hamiltonian→ 対角化 + ゲージ固定→ μ(rfill)→ 占有数→ k-path バンド→ simulation.h5

1_setup.jlJulia

パイプラインのドライバ。パラメータ Dict を1か所にまとめ、run_setup() 一発で 「読み込み → 対角化 → μ・占有数 → k-path → 保存」まで通す。冒頭の依存と定数は次のとおり。

1_setup.jl — 冒頭
using HDF5
using DelimitedFiles
using Printf
using LinearAlgebra

include("functions/nonint.jl")

const SIM_FILENAME = "simulation.h5"
パラメータ解説（このページの目玉）： 1_setup.jl の設定はすべて 1 つの params::Dict{String,Any} に集約されている。「ここだけ編集すれば OK」という設計で、 このスクリプトが使うもの（モデル記録・格子・グリッド・フィリング）と、 後段 FLEX / Eliashberg が読むものが同じ Dict に同居している。丸ごと simulation.h5 の params グループに保存されるため、 設定の単一の情報源（single source of truth）として下流の全スクリプトが参照する。
1_setup.jl · params（設定 Dict 全体）
params = Dict{String,Any}(
    # --- モデル（実体は hop.dat。ここは記録用メモ）---
    "model_t"      => 1.0,      # 最近接 t
    "model_tpp"    => -0.5,     # 第三近接 t''
    "model_t_perp" => 0.8,      # AA 層間 t_perp
    "hopping_path" => "./hop.dat",

    # --- 格子（BZ 形状・k-path 距離のため）---
    "lattice_type"   => "hex",
    "lattice_a"      => 1.0,
    "Norb_each_site" => [2, 2],  # 層1(A,B), 層2(A,B) → Norb=4
    "kpath_filename" => "KPOINTS",

    # --- 数値グリッド / 温度 ---
    "Nqx" => 32, "Nqy" => 32, "Nqz" => 1,
    "temperature" => 0.01,

    # --- フィリング ---
    # rfill = per-spin filling（spin 1つ分の占有数の総和, calc_mu_band の引数そのもの）。
    #   範囲 0..Norb。 full filled = Norb（軌道数）, half filling = Norb/2。
    #   全電子数（spin 2 込み） n_total = 2*rfill。
    #   ※ Norb=4 の今は rfill=4.0 で full, rfill=2.0 で half。
    "rfill" => 1.5,

    # --- FLEX / 相互作用（2_run_FLEX.jl 以降で使用）---
    "Nw"      => 32,       # 松原周波数の数（動作確認は軽め。本番は 1024 等）
    "U"       => 2.0,       # Hubbard U
    "Uprime"  => 0.0, "Jhund" => 0.0, "Jpair" => 0.0,
    "sub_self0"  => true,   # Σ から最小松原の実部を引く（第一原理バンド等で使用）
    "mix_factor" => 0.2,    # Σ の混合率
    "RPA"        => 0,      # 0=FLEX, 1=RPA（1回で止める）
    "flex_maxiter" => 2000,
    "flex_tol"     => 1e-5, # 収束判定（Σ の絶対誤差）
    "flex_eval_Uchi0_interval" => 10,
    # Stoner ガード: action = "abort" | "scale" | "continue"
    "flex_Uchi0_action" => "abort",
    "flex_Uchi0_warn_threshold" => 0.99,
    "flex_Uchi0_over_threshold" => 0.999,
    "flex_Uchi0_over_consecutive" => 10,
    "flex_is_Uchi0_scale" => false,
    "flex_maxeigval_tol"  => 0.99,
    # μ ソルバ切替（絶対誤差がこれ以上なら Brent、以下なら Secant）
    "flex_switch_solver_tol" => 2.0,
    "flex_min_dmu" => 0.1,
    "flex_max_dmu" => 1.0,

    # --- Eliashberg（3_run_eliashberg.jl 用）---
    # psym: 0/2=spm(s±), 1/3=dx2-y2, 5/6=dxy, 4=random（初期Δの対称性）
    # ssym: 1=singlet, 0=triplet, 2=no projection, 3=singlet+triplet 両方
    "psym" => 0,
    "ssym" => 3,
    "eliash_solver"  => "Lanczos",     # "Lanczos" | "PowerMethod"
    "eliash_howmany" => 2,             # 求める固有値の数（Lanczos のみ >1 可）
    "eliash_Lanczos_ncv" => 20,
    "eliash_Lanczos_maxiter" => 300,
    "eliash_Lanczos_which" => "LR",
    "eliash_Power_maxiter" => 1000,
    "eliash_tol" => 1e-5,
    "eliash_init_symmetry" => "from_psym",
    "eliash_init_seed" => 42,
)

① モデル（記録用メモ）

  • model_t / model_tpp / model_t_perp — 最近接 t、第三近接 t''、AA 層間 t⊥。実体は hop.dat 側にあり、ここの数値は計算に直接は使われない記録用メモ（どの gen_hop.py 設定で作った hop.dat かを simulation.h5 に残すため）。
  • hopping_path — 読み込む hop.dat のパス（既定 "./hop.dat"）。実際に load_Hamiltonian に渡すのはこれ。

② 格子

  • lattice_type="hex" / lattice_a=1.0 — 六方格子と格子定数。BZ 形状・k-path 距離を正しく測るための実空間ベクトル生成に使う（define_lattice_vectors）。
  • Norb_each_site=[2, 2] — サイトごとの軌道数。層1 の (A,B) で 2、層2 の (A,B) で 2 → Norb = sum = 4。この Norb が H(k) の行列サイズ・フィリング上限を決める。
  • kpath_filename="KPOINTS" — バンド図用の高対称点ファイル名。存在すれば k-path バンドを計算し、無ければその段だけスキップする（任意入力）。

③ 数値グリッド / 温度

  • Nqx,Nqy,Nqz = 32,32,1 — k メッシュ分割数。2D 系なので Nqz=1。この分割で load_Hamiltonian が正則メッシュ上の H(k) を作る（後段 FLEX の FFT もこの格子で回る）。
  • temperature=0.01 — 温度 T。フェルミ分布・松原周波数のスケールを決める（μ と占有数の評価に直結）。

④ フィリング rfill（重要）

  • rfill は per-spin filling＝スピン1つ分の占有数の総和で、calc_mu_band にそのまま渡す引数（Nfilling）。値域は 0..Norb。
  • 基準点：full filled = Norb（全軌道が埋まった状態）、half filling = Norb/2。いまは Norb=4 なので rfill=4.0 で full、rfill=2.0 で half。
  • 全電子数（スピン 2 込み）は ntotal = 2·rfill。既定 rfill=1.5 なら ntotal=3.0（4 軌道のうち平均 3 電子）。
  • この値が化学ポテンシャル μ を一意に決める目標量になる。範囲外（rfill<0 や rfill>Norb）を渡すと run_setup 冒頭のチェックで 即エラー停止する。

⑤ FLEX / 相互作用（2_run_FLEX.jl 以降で使用）

  • Nw — 松原周波数の本数。動作確認は軽め（32）、本番は 1024 等に上げる。U・Uprime・Jhund・Jpair は Hubbard 相互作用パラメータ（U=オンサイト、残りは軌道間・フント・ペアホッピング）。
  • sub_self0=true — Σ から最小松原成分の実部を引く静的補正（第一原理バンド等で μ と二重シフトしないため）。mix_factor=0.2 — SCF の Σ 線形混合率。RPA=0 — 0=FLEX / 1=RPA（1 回で止める）。
  • flex_maxiter / flex_tol — SCF の最大反復と収束判定（Σ の絶対誤差）。flex_eval_Uchi0_interval — Stoner 因子を評価する間隔。
  • Stoner ガード flex_Uchi0_* — Uχ0→1 の磁気不安定で発散するのを防ぐ安全弁。flex_Uchi0_action は "abort" | "scale" | "continue"、*_warn_threshold=0.99 / *_over_threshold=0.999 / *_over_consecutive=10 で警告・打ち切りの閾値と連続回数を、flex_is_Uchi0_scale / flex_maxeigval_tol で固有値の縮小を制御する。
  • μ ソルバ切替 flex_switch_solver_tol=2.0 — μ の絶対誤差がこれ以上なら Brent、以下なら Secant を使う。flex_min_dmu / flex_max_dmu は探索区間幅の下限・上限。

⑥ Eliashberg（3_run_eliashberg.jl 用）

  • psym — 初期ギャップ Δ の対称性。0/2 = s±（spm）、1/3 = dx²-y²、5/6 = dxy、4 = random。
  • ssym — スピン射影。1 = singlet、0 = triplet、2 = no projection（射影なし）、3 = singlet+triplet 両方。既定は psym=0, ssym=3。
  • eliash_solver="Lanczos"（"Lanczos" | "PowerMethod"）と eliash_howmany=2（求める固有値の数、Lanczos のみ >1 可）。
  • eliash_Lanczos_ncv / *_maxiter / *_which="LR"、eliash_Power_maxiter、eliash_tol — 各ソルバの反復・許容誤差。eliash_init_symmetry="from_psym" / eliash_init_seed=42 — 初期 Δ の生成規則と乱数シード。
⑤⑥ は 1_setup.jl では使われず、simulation.h5 の params にそのまま格納されるだけ。 実際に読むのは 2_run_FLEX.jl（⑤）と 3_run_eliashberg.jl（⑥）。ここに置くのは 「1 ファイルで全設定が見渡せる」ようにするため。
run_setup▶ セットアップ本体。読み込み→対角化→μ・占有数→k-path→simulation.h5 保存を一気通貫（引数なし）
run_setup() # params を読み、simulation.h5 と Noint/band_kpath.dat を書き出す

概要

params を展開して非相互作用セットアップの全工程を実行するドライバ関数。コードが長いので、 ソースの段階ごとに (a) パラメータ展開＋範囲チェック → (b) 格子・逆格子 → (c) H(k) 構築・対角化 → (d) μ・占有数 → (e) k-path バンド → (f) simulation.h5 保存 に分けて読む。数値の中身（H(k) 構築・ 対角化・μ 求根）は Nonint の関数に委ね、この関数は手順の配線に徹する。

(a) パラメータ展開＋ rfill 範囲チェック

1_setup.jl · run_setup（パラメータ展開）
Norb = sum(params["Norb_each_site"])
Nqx, Nqy, Nqz = params["Nqx"], params["Nqy"], params["Nqz"]
T = Float64(params["temperature"])
rfill = Float64(params["rfill"])     # = per-spin filling（0..Norb, full=Norb）
Nfilling = rfill                     # calc_mu_band の引数そのもの
hopping_path = params["hopping_path"]

# フィリングの範囲チェック（軌道数 Norb がマックス）
(0.0 <= rfill <= Norb) || error("rfill=$rfill is out of range [0, Norb=$Norb] (full filled = Norb).")
  • Norb = sum(params["Norb_each_site"]) — [2,2] の和で Norb=4。以降の行列サイズ・フィリング上限の基準になる。
  • rfill と Nfilling は同じ値（Nfilling=rfill）。名前を分けているのは「設定名（rfill）」と「calc_mu_band の引数名（Nfilling）」を対応づけて読みやすくするため。
  • (0.0 <= rfill <= Norb) || error(...) — フィリングが [0, Norb] の範囲外なら即エラー停止。|| は「左が真なら何もしない、偽なら右の error を実行」という Julia のガード構文。full filled = Norb を超える指定を弾く。

(b) 格子・逆格子ベクトル

1_setup.jl · run_setup（格子）
a1, a2 = define_lattice_vectors(; lattice_type=params["lattice_type"], a=Float64(params["lattice_a"]))
b1, b2 = reciprocal_vectors_2d(a1, a2)
  • define_lattice_vectors(; lattice_type="hex", a=1.0) — 実空間の基本ベクトル a1,a2 を作る（lattice.jl）。lattice_type と格子定数 a から六方格子を組む。
  • reciprocal_vectors_2d(a1, a2) — 2D の逆格子ベクトル b1,b2 を返す（lattice.jl）。後段の k-path 距離を正しい計量で測るために b1,b2 を build_kpath に渡す。

(c) H(k) 構築・対角化（＋ゲージ固定）

1_setup.jl · run_setup（H(k) と対角化）
println("Loading Hamiltonian from: $hopping_path")
ENERGY, hopping_df = load_Hamiltonian(hopping_path, Nqx, Nqy, Nqz, Norb; return_df=true)
Nrvec = size(hopping_df, 1) ÷ Norb^2

ENERGY_diag, UNITARY = diagonalize_Hamiltonian(ENERGY)
fix_unitary_gauge!(UNITARY)
  • load_Hamiltonian(...; return_df=true) — hop.dat を読み、正則 k メッシュ上の ENERGY[kx,ky,kz,i,j] を構築。return_df=true で 読み込んだ DataFrame も一緒に返す（後の k-path で再利用）。詳細は load_Hamiltonian。
  • Nrvec = size(hopping_df, 1) ÷ Norb^2 — 全行数を Norb²=16 で割って、1 軌道ペアあたりの R ベクトル数を求める（÷ は整数除算）。あとで simulation.h5 にメタとして保存する。
  • diagonalize_Hamiltonian(ENERGY) — 各 k で対角化し、バンド固有値 ENERGY_diag と固有ベクトル UNITARY を得る。ここでは SIGMA を渡さない＝純粋な非相互作用バンド。詳細は diagonalize_Hamiltonian。
  • fix_unitary_gauge!(UNITARY) — 固有ベクトルの k ごとのランダム位相を除去（in-place）。末尾の ! は破壊的更新の慣習。詳細は fix_unitary_gauge!。

(d) 化学ポテンシャル μ・占有数

1_setup.jl · run_setup（μ と占有数）
mu0 = calc_mu_band(ENERGY_diag, T, Nfilling)
Ne_band, Ne_orb = get_Ne_no_interaction(ENERGY_diag, T, mu0, UNITARY)
  • calc_mu_band(ENERGY_diag, T, Nfilling) — バンド固有値・温度・目標フィリングから、電子数が Nfilling に一致する化学ポテンシャル μ0を求根で決める（nonint.jl 由来）。ここが rfill を μ に翻訳する要。
  • get_Ne_no_interaction(ENERGY_diag, T, mu0, UNITARY) — 決まった μ0 のもとでバンド別占有数 Ne_band と軌道別占有数 Ne_orb を返す（nonint.jl 由来）。UNITARY でバンド→軌道の射影をかける。
  • 整合チェック：Σ Ne_band が rfill に、ntotal=2·Σ Ne_band が 2·rfill に一致するはず（スクリプトはこれをログ出力する）。

(e) k-path バンド（KPOINTS があれば）

1_setup.jl · run_setup（k-path バンド, 抜粋）
kpath_file = String(params["kpath_filename"])
has_kpath = isfile(kpath_file)
kpath_data = kpath_bandE = kpath_unitary = nothing
if has_kpath
    info = read_kpath_kpoints(kpath_file)
    kpath_data = build_kpath(info; b1_metric=b1, b2_metric=b2)
    Nk = length(kpath_data.kdist)
    Hk = hamiltonian_from_hopping_df(hopping_df, Norb, kpath_data.k_cart)
    kpath_bandE, kpath_unitary = diagonalize_Hk(Hk)

    # 目視用テキスト出力
    mkpath("Noint")
    band_table = Array{Float64}(undef, Nk, 5 + Norb)
    for i in 1:Nk
        band_table[i, 1] = i
        band_table[i, 2:4] .= collect(kpath_data.k_frac[i])
        band_table[i, 5] = kpath_data.kdist[i]
        band_table[i, 6:end] = kpath_bandE[i, :]
    end
    open(joinpath("Noint", "band_kpath.dat"), "w") do io
        write(io, "# idx kx_frac ky_frac kz_frac kdist band1..band$Norb  (Nk=$Nk)\n")
        writedlm(io, band_table)
    end
else
    println("KPOINTS not found: $kpath_file -> skip k-path band.")
end
  • has_kpath = isfile(kpath_file) — KPOINTS があるときだけ k-path バンドを計算し、無ければ else でスキップ。バンド図は任意成果物という位置づけ。
  • read_kpath_kpoints(kpath_file) → build_kpath(info; b1_metric=b1, b2_metric=b2) — 高対称点ファイルを読み、逆格子計量 b1,b2 でk-path（分数座標・デカルト座標・累積距離 kdist・目盛）を組む（nonint.jl 由来）。
  • hamiltonian_from_hopping_df(hopping_df, Norb, kpath_data.k_cart) — (c) で取っておいた DataFrame を使い、k-path 上の H(k) を構築（hamiltonian_from_hopping_df）。diagonalize_Hk(Hk) で Hermitian 対角化し、バンド kpath_bandE と固有ベクトル kpath_unitary を得る（diagonalize_Hk）。
  • band_table — Nk×(5+Norb) の表。列は idx, kx_frac, ky_frac, kz_frac, kdist, band1..bandNorb。mkpath("Noint") でディレクトリを作り、Noint/band_kpath.dat に 目視・作図用テキストとして書き出す。
  • -> skip k-path band. — KPOINTS が見つからないときのメッセージ。エラーではなく、この段だけ飛ばして先へ進む。

(f) simulation.h5 保存

1_setup.jl · run_setup（simulation.h5 保存, 抜粋）
h5open(SIM_FILENAME, "w") do file
    g_params = create_group(file, "params")
    for (k, v) in params
        v === nothing && continue
        g_params[k] = v
    end
    g_params["Norb"] = Norb
    g_params["Nfilling"] = Nfilling

    g_non = create_group(file, "nonint")

    g_ham = create_group(g_non, "hamiltonian")
    g_ham["ENERGY"] = ENERGY
    g_ham["Nrvec"] = Nrvec

    g_diag = create_group(g_non, "diag")
    g_diag["ENERGY_diag"] = ENERGY_diag
    g_diag["UNITARY"] = UNITARY
    attributes(g_diag)["gauge_fixed"] = true

    g_chem = create_group(g_non, "chem")
    g_chem["mu0"] = mu0
    g_chem["Ne_band"] = Ne_band
    g_chem["Ne_orb"] = Ne_orb

    g_lat = create_group(g_non, "lattice")
    g_lat["lattice_type"] = String(params["lattice_type"])
    g_lat["lattice_a"] = Float64(params["lattice_a"])
    g_lat["a1"] = a1; g_lat["a2"] = a2
    g_lat["b1"] = b1; g_lat["b2"] = b2

    if has_kpath
        g_kp = create_group(g_non, "kpath")
        g_kp["k_frac"] = k_frac_mat       # Nk×3 に整形して格納
        g_kp["k_cart"] = kpath_data.k_cart
        g_kp["kdist"]  = kpath_data.kdist
        g_kp["tick_pos"]   = kpath_data.tick_pos
        g_kp["tick_label"] = kpath_data.tick_label
        g_kp["band_energy"] = kpath_bandE
        g_kp["unitary"]     = kpath_unitary
        # ... k_cart_metric なども同様に保存
    end
end
  • h5open(SIM_FILENAME, "w") do file ... end — simulation.h5 を新規書き込みで開き、do ブロックを抜けると自動でクローズする。以降はグループ階層にデータを詰めていく。
  • params グループ — for (k,v) in params で設定 Dict を丸ごと保存。v === nothing && continue は「値が nothing の項目は書かずに飛ばす」ガード（HDF5 に nothing を書けないため）。加えて派生量 Norb / Nfilling も記録。
  • nonint/hamiltonian — 格子 H(k)（ENERGY）と Nrvec。nonint/diag — 対角化結果 ENERGY_diag / UNITARY。attributes(g_diag)["gauge_fixed"]=true でゲージ固定済みの目印を属性として残す。
  • nonint/chem — 化学ポテンシャル mu0 とバンド別・軌道別占有数 Ne_band / Ne_orb。後段はこの mu0 を μ の初期値に使う。
  • nonint/lattice — lattice_type / lattice_a と実空間・逆格子ベクトル a1,a2,b1,b2。BZ 形状や作図に使う。
  • nonint/kpath（has_kpath のときだけ）— k-path の分数/デカルト座標・累積距離 kdist・目盛（tick_pos / tick_label）・バンド band_energy・固有ベクトル unitary。バンド図をそのまま再現できる一式。
設計の勘所： run_setup 自身は「数値を解く」コードをほとんど持たず、 Nonint・Lattice の関数を正しい順序で呼び、結果を HDF5 に固める配線係。 重い一体計算はここで一度だけ済ませ、以降の FLEX/Eliashberg は simulation.h5 を読むだけで済む。
