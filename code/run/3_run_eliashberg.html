3. Eliashberg — 線形化ギャップ方程式

— __FLEX_CACHE__ の G・χ から線形化 Eliashberg を解き、固有値 λ とギャップ φ を得る  |  関数名をクリックで詳細 —

線形化 Eliashberg 方程式を解いて λ（超伝導不安定性）とギャップ φ を得るドライバ。 λ は Eliashberg 作用素の最大固有値で、λ=1 が超伝導転移点、λ が大きいほど不安定（Tc が高い）。 入力の G, χ0 は 2_run_FLEX.jl がメモリに置いた __FLEX_CACHE__ から受け取るため、同一 Julia セッションで連結実行することが前提（別プロセスでは動かない）。 数値ロジック本体は eliash_lib.jl 側にあり、このファイルは入出力と条件分岐の司令塔。

使い方： 同一セッションで include("2_run_FLEX.jl"); include("3_run_eliashberg.jl") （または compute.jl を実行）。
入力： __FLEX_CACHE__ の G・chi_0・UNITARY_corrected（大配列はメモリ経由）＋ simulation.h5 の params（温度・U・psym/ssym・ソルバ設定などのメタデータ）。
出力： simulation.h5 の eliashberg_result/{channel}/{lambda, phi_iwpm1_mode1to2}（小さい φ スライスのみ）＋ メモリの __ELIASH_CACHE__（フル φ）。
依存： include("functions/eliash_lib.jl")。
__FLEX_CACHE__ (G,χ0)→ 初期Δ（バンド基底→軌道基底）→ 射影（singlet/triplet）→ Eliashberg_pipeline!→ λ, φ→ __ELIASH_CACHE__ + eliashberg_result

projection_singlet! / projection_triplet!▶ ギャップ対称性の射影 Δ(iω,k)=±ΔT(-iω,-k)（singlet は対称化 +、triplet は反対称化 −）
projection_singlet!(DELTA) / projection_triplet!(DELTA) # 破壊的：DELTA を上書き

概要

クーパー対のギャップは、対の交換対称性から Δ(iω,k) = +ΔT(-iω,-k)（singlet）または Δ(iω,k) = -ΔT(-iω,-k)（triplet）を満たさなければならない。 この2関数は初期ギャップ（および反復中のギャップ）をその対称セクターへ射影する。 中身は「iω・k を反転し軌道 (i,j) を入れ替えた鏡像 rev」を作り、 singlet は加算、triplet は減算して 0.5 倍するだけ。

コード

3_run_eliashberg.jl · projection_singlet! / projection_triplet!
# ギャップ対称性の射影:  Δ(iω,k) = ± Δ^T(-iω,-k)
function projection_singlet!(DELTA)
    rev = similar(DELTA)
    permutedims!(rev, DELTA[end:-1:1, [1; end:-1:2], [1; end:-1:2], [1; end:-1:2], :, :], (1, 2, 3, 4, 6, 5))
    DELTA .+= rev
    DELTA .*= 0.5
    return nothing
end
function projection_triplet!(DELTA)
    rev = similar(DELTA)
    permutedims!(rev, DELTA[end:-1:1, [1; end:-1:2], [1; end:-1:2], [1; end:-1:2], :, :], (1, 2, 3, 4, 6, 5))
    DELTA .-= rev   # ← singlet との唯一の差：加算(+) ではなく減算(−)
    DELTA .*= 0.5
    return nothing
end

読み方

  • DELTA は 6 次元 [iω, kx, ky, kz, i, j]（周波数・波数・軌道ペア）。rev = similar(DELTA) は同形の出力バッファ。
  • DELTA[end:-1:1, …] — 第 1 軸（iω）を反転して iω → -iω。
  • [1; end:-1:2] — 波数 3 軸それぞれの反転（先頭 index 1 は固定、残りを逆順）。fftfreq 並びでの k → -k に対応。
  • 置換 (1, 2, 3, 4, 6, 5) — 最後の 2 軸（軌道 i,j）を入れ替え＝軌道空間の転置。合わせて rev = ΔT(-iω,-k)。
  • DELTA .+= rev; DELTA .*= 0.5 — (Δ + ΔT(-iω,-k))/2 で singlet 成分だけ残す対称化射影。triplet は .-= で (Δ − ΔT(-iω,-k))/2 の反対称化。
  • permutedims!（末尾 !）は rev にその場書き込み。関数末尾 ! は DELTA を破壊的に更新する慣習。
物理： フェルミオンの反交換から、対の波動関数（＝異常ギャップ Δ）はスピン・軌道・空間・時間の全交換で符号 -1。 スピン singlet（反対称）なら残り（軌道・k・iω）は偶、triplet（対称）なら奇。この射影は初期ゲスから 「許されない対称性の混入」を落とし、目的セクターの固有ベクトルへ収束させるためのもの。
関連：Eliashberg_pipeline!（射影関数を projection_func として受け反復中も適用）／ projection_none!（射影しない版）
projection_none!▶ 何もしない射影（ssym=2・射影なしで生の固有値を見るとき用）
projection_none!(DELTA) = nothing

概要

対称性の射影を一切かけないダミー。ssym=2（"none"）のとき、 singlet/triplet のどちらにも押し込めず、Eliashberg 作用素そのものの最大固有値を素直に見たい場合に使う。 Eliashberg_pipeline! に projection_func として渡され、呼ばれても即 nothing を返す。

_extract_phi_iwpm1▶ フル φ から ±iω1・mode 1..2 の最小スライスだけ抜く（プロット・保存用）
_extract_phi_iwpm1(phi::Array{ComplexF64,7}; nmodes=MIN_SAVE_NMODES) → Array{ComplexF64,7}（第1軸サイズ 2）

概要

フルの φ は 7 次元 [iω, kx, ky, kz, i, j, mode] で大きい。HDF5 には全部を書かず、 最低周波数 +iω1・-iω1 の 2 枚と mode 1..MIN_SAVE_NMODES（=2）だけを 取り出した軽量スライスを作る。6_plot_eliashberg.jl が描くギャップ構造にはこの iω1 面で十分。

コード

3_run_eliashberg.jl · _extract_phi_iwpm1
# ±iw1, mode1..MIN_SAVE_NMODES の最小 φ スライス（プロット用）
function _extract_phi_iwpm1(phi::Array{ComplexF64,7}; nmodes::Int=MIN_SAVE_NMODES)
    iw_pos, iw_neg = 1, size(phi, 1)
    mmax = min(nmodes, size(phi, 7))
    out = Array{ComplexF64}(undef, 2, size(phi, 2), size(phi, 3), size(phi, 4), size(phi, 5), size(phi, 6), mmax)
    @views out[1, :, :, :, :, :, 1:mmax] .= phi[iw_pos, :, :, :, :, :, 1:mmax]
    @views out[2, :, :, :, :, :, 1:mmax] .= phi[iw_neg, :, :, :, :, :, 1:mmax]
    return out
end

読み方

  • iw_pos, iw_neg = 1, size(phi, 1) — +iω1 は周波数軸の先頭、-iω1 は末尾（fftfreq 並びの両端）。
  • mmax = min(nmodes, size(phi, 7)) — 保存する mode 数を MIN_SAVE_NMODES で頭打ち（固有ベクトルが 1 本しか無い場合も安全）。
  • out の第 1 軸サイズは 2 — [+iω1, -iω1] の 2 面だけを積む。定数 MIN_PHI_KEY のコメント「iw 順: [+iw1, -iw1]」と一致。
  • @views … .= phi[…] — スライス右辺の一時配列生成を抑えて直接コピー。
設計意図： フル φ は周波数×k×軌道×mode で巨大なので HDF5 に丸ごと置くとファイルが膨れる。 可視化に要る最小面だけディスクへ、フルはメモリ（__ELIASH_CACHE__）へと役割分担する。
関連：MIN_PHI_KEY / MIN_SAVE_NMODES（保存キーと mode 数）／ 6_plot_eliashberg.jl（このスライスを描く）
_get_flex_cache▶ Main.__FLEX_CACHE__ の存在・中身を検査し、無ければ「先に 2_run_FLEX.jl を同一セッションで」と即エラー
_get_flex_cache() → Main.__FLEX_CACHE__（Dict）／ 不正なら error(...)

概要

入力の大配列 G・χ0 は 2_run_FLEX.jl がグローバル __FLEX_CACHE__ に置いたものを使う。 この関数はそれが定義済みで・Dict で・:G と :chi_0 を持つことを確認し、 欠けていれば「同一 Julia セッションで先に 2_run_FLEX.jl を回せ」という親切なエラーで止める。

コード

3_run_eliashberg.jl · _get_flex_cache
function _get_flex_cache()
    ok = isdefined(Main, :__FLEX_CACHE__) && (Main.__FLEX_CACHE__ isa AbstractDict) &&
         haskey(Main.__FLEX_CACHE__, :G) && haskey(Main.__FLEX_CACHE__, :chi_0)
    ok || error("__FLEX_CACHE__ not found. Run 2_run_FLEX.jl in the SAME Julia session first " *
                "(e.g. include(\"2_run_FLEX.jl\"); include(\"3_run_eliashberg.jl\"), or use compute.jl).")
    return Main.__FLEX_CACHE__
end

読み方

  • isdefined(Main, :__FLEX_CACHE__) — グローバルに存在するか。別プロセス実行だと未定義になり、ここで弾かれる。
  • … isa AbstractDict && haskey(…, :G) && haskey(…, :chi_0) — 型が Dict で、必要キー :G・:chi_0 が揃うかを && で連結チェック。
  • ok || error(...) — どれか欠ければ即エラー。メッセージが正しい連結実行の仕方を提示（include 2 連 or compute.jl）。
  • 成功時は Main.__FLEX_CACHE__ をそのまま返す（コピーしない＝大配列は参照渡し）。
連結実行が前提： __FLEX_CACHE__ はメモリ上のグローバルで、ディスクには無い。 2_run_FLEX.jl を回した Julia を終了したり、別プロセスで 3_run_eliashberg.jl だけ起動すると必ずここで失敗する。 必ず同一セッションで include を続けること。
関連：2_run_FLEX.jl（__FLEX_CACHE__ を作る側）

(1) 入力：params は HDF5、大配列は __FLEX_CACHE__

3_run_eliashberg.jl · run_eliashberg（入力）
function run_eliashberg()
    log_banner("ELIASHBERG (linearized)")

    # --- 入力: params は HDF5、大配列は __FLEX_CACHE__（メモリ連結）---
    cache = _get_flex_cache()
    params = Dict{String,Any}()
    h5open(SIM_FILENAME, "r") do file
        for k in keys(file["params"])
            params[String(k)] = read(file["params"][k])
        end
    end
    G = cache[:G]
    CHI0 = cache[:chi_0]
    UNITARY = get(cache, :UNITARY_corrected, nothing)
    println("Using __FLEX_CACHE__ (G, chi_0" * (UNITARY === nothing ? "" : ", UNITARY_corrected") * ")")
  • cache = _get_flex_cache() — 先に __FLEX_CACHE__ の健全性を確認して取得。
  • h5open(SIM_FILENAME, "r") do file … end — simulation.h5 の params グループを全キー読み Dict 化。小さいメタデータだけディスク経由。
  • G = cache[:G] / CHI0 = cache[:chi_0] — 大配列はメモリから直接参照。ディスクを介さない。
  • UNITARY = get(cache, :UNITARY_corrected, nothing) — バンド↔軌道変換用のユニタリ。無ければ nothing（後段で分岐）。

(4) 初期Δ生成とチャネル実行（ネスト関数）

3_run_eliashberg.jl · _make_delta0 / _run_one（ネスト関数）
    # バンド基底で初期 Δ0 を作り、必要なら軌道基底へ変換
    function _make_delta0(spin_symmetry)
        D = copy(G)
        init_DELTA_band!(D; symmetry=init_symmetry, spin_symmetry=spin_symmetry, seed=init_seed)
        UNITARY === nothing || band2orb_anomalous!(D, UNITARY)
        return D
    end

    function _run_one(spin_symmetry, projection_func)
        log_section("solve ($spin_symmetry)")
        CHI = copy(CHI0)
        DELTA = _make_delta0(spin_symmetry)
        projection_func(DELTA)
        @time lambda, phi = Eliashberg_pipeline!(
            DELTA, G, CHI, U_spin, U_charge, temp, FFT_plan;
            mask_inds=mask_inds, spin_symmetry=spin_symmetry,
            solver=solver, howmany=howmany, Lanczos_ncv=Lanczos_ncv,
            Lanczos_maxiter=Lanczos_maxiter, Lanczos_which=Lanczos_which,
            Power_maxiter=Power_maxiter, tol=tol, return_half=false, projection_func=projection_func)
        return lambda, phi
    end
  • _make_delta0：D = copy(G) を器に init_DELTA_band! でバンド基底の初期ギャップを対称性付きで生成し、UNITARY === nothing || band2orb_anomalous!(D, UNITARY) でユニタリがあれば軌道基底へ変換（band2orb_anomalous!）。
  • _run_one：CHI = copy(CHI0) で χ0 を複製（パイプライン内で Veff に上書きされるため、元を守る）。
  • 初期Δに projection_func(DELTA) で対称性を射影 → Eliashberg_pipeline! に投げて lambda, phi を得る。@time で 1 チャネルの実行時間を計測。
  • return_half=false＝フル φ を返す。projection_func は反復の各ステップでも対称性を保つためパイプラインへも渡す。

(5) チャネル選択：ssym で singlet / triplet / none / both

  • 各分岐は _run_one(スピン対称性, 射影関数) を呼ぶだけ。ラベルがそのまま HDF5 の {channel} 名になる。

        attributes(g)["howmany"] = howmany
        for (label, (lambda, phi)) in results
            gch = create_group(g, label)
            gch["lambda"] = lambda
            gch[MIN_PHI_KEY] = _extract_phi_iwpm1(phi)
            attributes(gch)["min_phi_iw_order"] = "+iw1,-iw1"
        end
    end
    log_banner("ELIASHBERG DONE")
end

run_eliashberg()
  • 表示：各チャネルの λ を mode1=… mode2=… の形で 1 行に。実部 real(x) のみ表示。
  • メモリ保存：__ELIASH_CACHE__ が無ければ生成し、lambda_<label>・phi_<label> にフル配列を格納（後段の解析用）。
  • HDF5 保存：haskey(file, GROUP_NAME) && delete_object(...) で既存 eliashberg_result を消してから作り直す（再実行で上書き）。
  • グループ属性に ssym・ssym_label・howmany。各チャネルに lambda と _extract_phi_iwpm1(phi) の最小 φ スライスを MIN_PHI_KEY で書く。
  • 末尾のトップレベル run_eliashberg() — include された瞬間に実行される（連結実行の締め）。
大配列の置き場所： フル φ はメモリ（__ELIASH_CACHE__）だけ、HDF5 には λ と ±iω1 の 最小スライスしか残さない。フル φ が要る解析は同一セッションで __ELIASH_CACHE__ から取ること。 セッションを閉じるとフル φ は失われる（再計算が必要）。
関連：Eliashberg_pipeline! / init_DELTA_band! / _psym_to_init_symmetry / _parse_Lanczos_which／ band2orb_anomalous!／ get_interaction_matrices / get_mask
連結実行が絶対条件： G・χ0 はディスクではなく __FLEX_CACHE__（メモリ）から受け取る。 include("2_run_FLEX.jl"); include("3_run_eliashberg.jl") のように同一 Julia セッションで続けて呼ぶこと。 別プロセスで 3_run_eliashberg.jl 単体を起動すると _get_flex_cache() で必ず失敗する。
λ の読み方： λ は Eliashberg 作用素の最大固有値。λ=1 で超伝導転移（このギャップ構造が自己無撞着に立つ点）、 λ<1 は常伝導、λ が大きいほど不安定＝Tc が高い。温度を下げながら λ(T) が 1 を横切る温度が Tc の目安。 singlet/triplet の射影は、対の反対称性 Δ(iω,k)=±ΔT(-iω,-k) のうち物理的に許される対称セクターだけを拾うためのもの。
